# Task 3.1 — Volume Pane (dual-axis, verified)

Status: DONE (index: TASKS/README.md)
Depends on: 2.2
Goal: Volume pane renders below the price candles on a separate right-hand axis, visually confirmed — not just code that "should" work.

## Why (audit findings)
- Current single-chart approach puts candles + volume bars in ONE Chart instance with two y-axes (`y-price` left, `y-volume` right) and one shared x-axis. That is a valid Chart.js pattern, but it has never rendered (2.2 bugs), and old docs claim "multi-pane candlestick chart (price + volume)" as working — false.
- The Python app uses a true multi-PANE layout (chart/pane_manager.py) with panes stacked vertically. Chart.js equivalent choice must be explicit: **single canvas + dual axis (current)** vs **two canvases + synced axes**.

## Decision (v1 → REVISED per Kevin, 2026-09-24)
~~Keep single canvas + dual y-axis~~ — **REVISED**: the live pixel-verified screenshot
(docs/screenshots/3.1-volume-pane-msft.png) shows the v1 approach FAILS the visual
requirement: volume bars (0-200M scale) share the plot area with candles and tower
over them — the candlestick action is compressed and unreadable. Kevin approved
TradingView-style renditions ("almost exactly like TradingView") — TradingView puts
volume in its OWN bottom pane (~20% height, never overlapping). **Task 10.4 (true
multi-pane layout) is pulled INTO 3.1** — Ruling 7.

## Steps
1. **Test-first** (extend viewer spec):
   - With mocked OHLCV data: chart config contains a dataset `type:'bar'` with `yAxisID:'y-volume'`, and scales config has `y-price` (position left) + `y-volume` (position right, `grid.drawOnChartArea:false`).
   - Volume dataset data maps each OHLCV point to `{x: timestamp, y: volume}`.
2. Implementation: verify the existing config satisfies the spec; fix where it doesn't (e.g. bar `base` so bars start at 0; volume axis `max` normalized to data to keep candles readable; candle color functions using CSS variables — defer token work to 6.2).
3. `maintainAspectRatio:false` + container CSS so the canvas fills the flex column (styles in component SCSS vars — no inline).
