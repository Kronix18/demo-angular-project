# Task 5.2 — Indicator Panel Component

Status: DONE (browser-verified 2026-09-29)
Depends on: 5.1
Goal: The existing `indicator-panel` stub becomes real: renders indicator series as overlays (price-pane) or separate panes (oscillators), driven by chart state.

## Why (audit findings)
- `indicator-panel` was generated (`--skip-tests`) in a previous session and never wired — dead stub.
- Chart.js: indicators like SMA/EMA overlay the price pane (same y-axis); RSI/WebbyRSI/BobMarley are oscillators needing their OWN pane (separate canvas below price+volume, matching Python's pane_manager model in simplified form).

## Steps
1. **Test-first** (`indicator-panel.component.spec.ts`):
   - Renders one row/button per ACTIVE indicator from state.
   - Overlay vs pane classification: `sma`/`ema` → overlay; `rsi`/`webby_rsi`/`bob_marley` → pane (assert via a classification map exported from the service).
   - Toggling an indicator adds/removes its dataset from the chart (spy on chart.data update + update()).
2. Implementation:
   - Indicator datasets: line type, colored via CSS vars, `yAxisID` = price axis for overlays.
   - Oscillator pane: second `<canvas>` below main chart (component template), own Chart instance, synced x-range via zoom plugin events or state (keep simple: shared state range re-render — full axis sync is v2, note it).
   - ATR: overlay as line on price axis (scale mismatch noted) — decision: ATR on price axis *100 factor is wrong; put ATR in the oscillator pane instead. Document.
3. Wire state: indicators list in ChartStateService (from 4.1) drives the panel; toggling persists to sessionStorage via store.
