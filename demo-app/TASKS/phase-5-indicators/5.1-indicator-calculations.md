# Task 5.1 — Indicator Calculations (port the real Python calculators)

Status: DONE (unit-verified 2026-09-29)
Depends on: 2.2, 0.2 (inventory)
Goal: Port the 5 real Python indicator calculators to TypeScript with golden-value tests: SMA/EMA (`moving_average.py`), RSI (`rsi.py`), ATR (`atr.py`), Webby RSI (`webby_rsi.py` + `webby_rsi_core.py`), Bob Marley (`bob_marley.py`).

## Why (audit findings)
- Old plan listed generic "SMA, EMA, Volume indicators" — does NOT match the actual Python registry (`indicators/registry.py`, calculators: moving_average, rsi, atr, webby_rsi, bob_marley).
- Current `IndicatorCalculationService` is a TODO stub returning `[]`.
- "Verify calculations match Python reference" (old plan) needs a concrete method: golden values generated FROM the Python code itself.

## PORT-INVENTORY CORRECTIONS (ruling from 0.2 findings, 2026-09-23 — see docs/PORT-INVENTORY.md §4.3)
- **6 calculator files, not 5**: `webby_rsi_core.py` holds the actual Webby RSI math (ema, sma, wilder_atr, original, version_5150); `webby_rsi.py` is only a mode dispatcher. Port both.
- **Wilder/RMA semantics = pandas `ewm(alpha=1/N, adjust=False, min_periods=N)`** — ewm starts from the first value, NOT the textbook SMA-seed-then-recurrence. Golden tests MUST be generated from the Python files using these exact semantics or they will diverge.
- Moving Average supports 4 methods (SMA/EMA/WMA/RMA) + source (open/high/low/close/hl2/hlc3/ohlc4/volume via `resolve_source`) + offset param.
- RSI: `delta.clip` gains/losses, Wilder ewm, flat-input→50.0, no-loss→100.0; overbought/oversold constant-filled arrays.
- Registry order: moving_average, atr, rsi, webby_rsi, bob_marley (sorted by (category,name) for the menu).
- Full param schemas are in docs/PORT-INVENTORY.md §4.1-4.3 — use them verbatim, do not re-derive.

## Steps
1. Generate golden values: for each calculator, run the PYTHON implementation over a fixed fixture (use a slice of real msft.us.txt data, e.g. 100 bars) and dump `{input_hash, params, output[]}` JSON into `src/app/core/indicators/__fixtures__/`. Script kept at `scripts/gen_indicator_fixtures.py` (in demo-app, run manually; screener repo read-only).
2. **Test-first** (`indicator-calculation.service.spec.ts`):
   - For each of the 5 indicators: service output matches golden fixture within 1e-6.
   - Edge cases: warmup period (SMA window > data length → []), insufficient bars, NaN handling.
   - Input contracts: series of OHLCV (ATR needs H/L/C; RSI needs closes).
3. Implementation in `IndicatorCalculationService`:
   - Port each algorithm reading the Python source FIRST (translate its exact rounding/seed/Wilder-smoothing semantics — do NOT use textbook formulas that differ).
   - Registry-shaped API: `calculate(type, params, ohlcv)` + `supportedIndicators` list mirroring `registry.py`.
4. Document each indicator's params schema (periods etc.) in this file after reading the Python source.
