# Task 2.2 — Chart.js Registration & Date Adapter

Status: NOT STARTED
Depends on: 2.1
Goal: `new Chart(...)` actually constructs and renders a candlestick chart with a working time axis.

## Why (audit findings — chart never renders)
- `chart-viewer.component.ts` imports `Chart` and `registerables` but NEVER calls `Chart.register(...registerables)` → every chart construction throws `"... is not a registered scale/controller".
- Time scale needs a date adapter: `chartjs-adapter-date-fns` is installed but never imported → second hard failure.
- `registerables` registration also required for the zoom plugin (3.2) to work later.
- Chart destroyed on reload path exists (good) but chart creation happens while `*ngIf` hides the canvas (`loading=true` initially hides `#chartView` template) → `@ViewChild` is undefined when data arrives → `ctx` null crash. **Timing bug: must render canvas before createChart.**

## Steps
1. **Test-first** (`chart-viewer.component.spec.ts` extend):
   - Spies on `Chart` static `register` — component import registers registerables + date-fns adapter (can assert via `Chart.registry` contains 'candlestick' controller after module import).
   - After `detectChanges` with mocked data: `loading === false`, canvas element EXISTS in DOM, and `window.Chart` instance created (spy on constructor).
   - Error path: service throws → `error` message rendered, canvas absent is OK.
2. Implementation:
   - Module-level (top of chart-viewer.component.ts): `import 'chartjs-adapter-date-fns'; Chart.register(...registerables);`
   - Fix canvas timing: swap `*ngIf` for `[hidden]`-style flow OR create chart in `ngAfterViewInit` after data resolves AND view re-rendered — simplest: keep canvas always in DOM (`*ngIf` only on error message), overlay "Loading..." as a separate element.
3. Verify chartjs-plugin-zoom is registered too (import + `Chart.register(zoomPlugin)`) so 3.2 has the ground prepared.
