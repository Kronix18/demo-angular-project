# Task 1.2 — Navbar Composition Fix (the user's blocking complaint)

Status: DONE (unit + build + served-bundle verified; live-browser run of scripts/verify-1-2.cjs is the controller's step — see Verification results)
Depends on: 1.1
Goal: Navbar correctly composed in both auth states: always Home/Screener/Pricing/Charts links; right side shows Login+Register when logged out, My Account + Logout when logged in. No "✓ Logged In" badge — an actual account link instead.

## Why (audit findings)
- `app.html` hides Screener/Profile behind `*ngIf="isAuthenticated"` → logged-out users see ONLY Pricing (user's complaint). Home link missing from nav-links entirely.
- Right side shows a passive "✓ Logged In" span; user explicitly asked for "your/my account or something like that".
- `app.spec.ts` is a stale scaffold asserting "Hello, demo-app" → fails today; must be rewritten with the component.

## Decision (acting on user's description, standard pattern)
- Nav links (always visible): Home, Screener, Pricing, Charts (added in 6.1 — placeholder allowed now if route exists; Charts link formally lands in 6.1).
  Route protection is done by guards (1.3), not by hiding links.
- Right side logged OUT: Login, Register.
- Right side logged IN: "My Account" (routerLink /profile, shows user email as title/aria) + Logout button.

## Test-first (RED)
Rewrite `src/app/app.spec.ts` (replacing stale "Hello, demo-app" test):
1. Logged-out state: renders Home, Screener, Pricing links; does NOT render My Account or Logout; renders Login + Register.
2. Logged-in state (seed sessionStorage or emit via AuthService): renders My Account + Logout; does NOT render Login/Register.
3. Logout click → AuthService.logout called + router navigates to /auth/login.
4. No element in the rendered navbar uses inline `style` attributes (design-token compliance rule).

Run `ng test` → new tests FAIL (RED; the old stale test also goes red/green transition here). Commit: `test: navbar composition specs (RED)`.

## Implementation (GREEN)
- Update `app.html` per the decision above (template only — no logic changes needed; `App` class already subscribes to `isLoggedIn$`).
- Remove the "✓ Logged In" span; add My Account link with `*ngIf="isAuthenticated"`.
- Styling: reuse existing `app.scss` classes; NO new inline styles; hardcoded colors moved to CSS custom properties in 6.2 (allowed to defer).

- Log in → screenshot logged-in navbar (My Account + Logout, no Login/Register).
- Logout → back to logged-out state, redirected to /auth/login.
- Console clean; both screenshots to `docs/screenshots/`.
