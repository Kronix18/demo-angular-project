# Task 4.1 — Chart State Service (moved BEFORE toolbar refactor)

Status: DONE (index: TASKS/README.md)
Depends on: 2.3
Goal: Central `ChartStateService` (BehaviorSubject store) holding symbol, interval, range, and active indicators; toolbar and viewer both talk to the store, not to each other.

## Why (audit findings — plan reorder)
- Old plan had "5.1 Chart State Service" AFTER the toolbar integration (old 3.x) — backwards: the toolbar was already emitting events directly to the viewer, creating the exact coupling that needs a store. Reordered to Phase 4 before further toolbar work.
- Session persistence exists in AuthService only; chart state loses symbol/interval on refresh today (route param is the only carrier).
- Python equivalent: `state/app_state.py` + `state/chart_settings.py` — port target.

## Steps
1. **Test-first** (`chart-state.service.spec.ts`):
   - Holds defaults `{symbol:'msft', interval:'1d', range:'6m', indicators:[]}`.
   - `setSymbol('nvda')` → `state$` emits with symbol nvda, others unchanged.
   - `setInterval('1w')`, `setRange('1y')` similar.
   - Persists to sessionStorage under key `chart-state` on change; rehydrates on service construction (seed before inject, like 1.1).
   - `reset()` restores defaults and clears storage.
2. Implementation:
   - `src/app/core/services/chart-state.service.ts`: private BehaviorSubject + `select()` helpers; `provideHttpClient` unaffected.
   - Toolbar (4.2) and viewer subscribe; viewer derives data loads from state changes (distinct-until-changed), toolbar is write-only.
3. Wire chart-viewer to load from state, keeping route param as initial seed (`route.paramMap` → `setSymbol` once).

## Verification (browser)
- `/charts/msft` → change symbol via toolbar (post-4.2 or manual console) → state reflects (devtools: sessionStorage.chart-state shows symbol).
- Refresh → symbol/interval survive (chart re-renders same symbol).
- Console clean.
