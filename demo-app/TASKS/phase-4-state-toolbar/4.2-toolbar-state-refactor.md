# Task 4.2 — Toolbar Refactor onto State Service

Status: NOT STARTED
Depends on: 4.1
Goal: Toolbar becomes a dumb component: writes to ChartStateService, no @Output events, no direct viewer coupling.

## Why (audit findings)
- Current toolbar emits `@Output` events consumed by viewer handlers — works but couples components and duplicates state (`currentSymbol`/`currentInterval` in viewer + `symbol`/`interval` in toolbar = 4 copies of truth).
- After 4.1 the store is single source of truth; toolbar only writes, viewer only reads.
- Toolbar has dead code: injected `FormBuilder` (unused), unused `symbols` array, redundant `updateChart()` double-emit path.

## Steps
1. **Test-first** (rewrite toolbar spec):
   - Symbol input + Enter → `ChartStateService.setSymbol` called with input value (spy), NOT any EventEmitter.
   - Interval select change → `setInterval` called.
   - Toolbar template initializes input/select values FROM the state$ stream (sync test: state symbol 'nvda' → input value 'nvda').
   - No `@Output` properties remain on the class.
2. Implementation:
   - Remove `@Output symbolChange/intervalChange`, remove viewer handlers `onToolbarSymbolChange/onToolbarIntervalChange` (viewer now subscribes to state).
   - Toolbar constructor/state subscription sets local form values once (avoid feedback loops: only write on user action).
   - Delete dead FormBuilder/symbols members.
3. Update 2.3's URL-sync behavior: state changes drive `router.navigate(['/charts', symbol])` in viewer (replaceState), not toolbar.

## Verification (browser)
- Same flows as 2.3 (symbol change → URL + chart update; no per-keystroke requests).
- Toolbar input shows current symbol after refresh (state rehydration).
- Console clean. Screenshots.
