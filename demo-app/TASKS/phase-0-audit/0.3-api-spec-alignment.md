# Task 0.3 — API Backend Spec Alignment

Status: DONE
Depends on: 0.2
Goal: `API-BACKEND-SPEC.md` matches reality: the demo runs on Stooq daily-only test files until the backend exists, and the spec's contract matches what the frontend will actually consume.

## Why (audit findings)
- Spec promises intervals 1m/5m/1h/1d/1w/1M, but the test data (`test data/*.us.txt`) contains ONLY daily (`PER=D`) rows from 1986 onward. Intraday cannot be demoed until the backend exists.
- Spec says `timestamp: number (Unix milliseconds)` — good, but the current frontend parses `YYYYMMDDHHMMSS` as an integer (fixed in 2.1); the spec must be the single source of truth for the unit.
- No error-shape or 404 contract (needed by 6.3 error states).

## Steps
1. Update `API-BACKEND-SPEC.md`:
   - Add a "Current demo data source" section: Stooq daily `.us.txt` files served from `public/test-data/`, listing the 8 available symbols (ia, msft, mu, nvda, pltr, qqew, qqq, qqqe — NOTE: no AAPL).
   - Fix interval list: mark 1d/1w as demo-available (client-side weekly aggregation OK), 1m/5m/1h as backend-only.
   - Standardize: `timestamp` is Unix epoch milliseconds everywhere.
   - Add error response shape + HTTP status contract (404 unknown symbol, 400 bad interval) for task 6.3.
   - Add `symbol` normalization rule (uppercase; `.US` suffix stripped in URLs and re-added by backend).
2. Cross-check the OHLCV endpoint shape against `src/app/core/models/ohlcv.model.ts` field names.
