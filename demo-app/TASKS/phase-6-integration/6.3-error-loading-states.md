# Task 6.3 — Error & Loading States

Status: NOT STARTED
Depends on: 2.1, 6.1
Goal: Chart page degrades gracefully: skeleton while loading, clear error (unknown symbol, empty file) with retry, no dead "Loading chart..." forever state.

## Why (audit findings)
- Current loading state is a plain `<p>Loading chart...</p>`; error path sets a message but the flow has never been exercised (data always 404'd until 2.1).
- With 8 symbols only, unknown-symbol UX matters: `/charts/aapl` (user's own example!) is an error case today. Message must list available symbols.
- No retry mechanism anywhere (old plan 6.4 promised it; nothing exists).

## Steps
1. **Test-first** (viewer spec extend):
   - Service emits `[]` (unknown symbol) → error element visible with symbol name + available-symbols hint + Retry button.
   - Retry click → re-invokes load (spy).
   - Loading → skeleton element present while fetching (assert class), absent after.
   - Error → chart canvas hidden, no stale chart instance.
2. Implementation:
   - Template: skeleton (CSS-only shimmer via token animation), error card, retry wired to `loadChartData`.
   - `ChartDataService` exposes `AVAILABLE_SYMBOLS = ['ia','msft','mu','nvda','pltr','qqew','qqq','qqqe']` (single source; toolbar datalist in 2.3 uses it too).
   - Distinguish 404 (unknown symbol) from parse errors in the catch path.
3. Ensure loading never stays stuck: finalize via `finalize()` operator.

## Verification (browser)
- `/charts/aapl` → friendly error with symbol list + Retry (screenshot); `/charts/msft` → skeleton then chart.
- Kill dev server mid-load (or throttle network) → error appears, Retry works after restore.
