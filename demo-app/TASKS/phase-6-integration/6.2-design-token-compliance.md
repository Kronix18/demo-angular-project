# Task 6.2 — Design Token Compliance (CSS custom properties only)

Status: NOT STARTED
Depends on: 1.2, 3.1 (components exist first)
Goal: Zero hardcoded colors/sizes outside the theme file; all component styling flows through CSS custom properties — enforcing your stated constraint.

## Why (audit findings — constraint currently violated)
- `app.scss` hardcodes `#f8f9fa`, `#667eea`, `#764ba2`, white, rgba() values throughout.
- Chart components hardcode colors: `rgba(75,192,192,...)` volume bars, `'green'/'red'` candles, white text.
- Constraint from project rules: all styling in CSS custom properties in a single SCSS file; no inline styles.
- JS-computed colors (candle green/red functions) must read CSS vars at runtime via `getComputedStyle` (pattern already sketched in 3.3).

## Steps
1. **Test-first** (style-guard specs):
   - `styles.spec.ts` (new): read `src/styles.scss` + `src/styles/theme-system.scss` — assert every color literal in app/charts SCSS files is `var(--...)`, i.e. regex-scan component SCSS for `#[0-9a-f]{3,8}|rgba?\(` outside of the theme file → must be zero matches (allow `rgba(var(--x-rgb), a)` form).
   - App spec (from 1.2) already asserts no inline `style` attributes in navbar — extend to chart viewer render.
2. Implementation:
   - Define the full token set in the theme file: `--c-bg`, `--c-bg-gradient-a/b`, `--c-text`, `--c-primary`, `--c-up`, `--c-down`, `--c-volume`, `--c-crosshair`, `--c-border`, spacing/radius/shadow tokens.
   - Replace every hardcoded color in app.scss, chart-viewer, toolbar, indicator panel, login/error elements.
   - Chart.js runtime colors: helper `cssVar(name)` reading `getComputedStyle(document.documentElement)`; used by candle color fn, volume bar, crosshair, grid lines, tooltip colors.
3. Check `styles.css` bundle actually contains the custom properties (build output grep).
